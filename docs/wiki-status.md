## Как обновлять GitHub после партии

1. Получить production receipt и проверить опубликованные страницы.
2. Обновить приватный Excel по стабильным ID, затем план и QA партии.
3. Добавить `docs/wiki-updates/<дата>-<партия>.md`: batch_id, число новых
   и обновлённых материалов, названия и ссылки на wiki, фактическая проверка.
   Повтор того же batch_id не создаёт новую запись; исправление получает revision
   и новый batch_id. Обновлённые страницы учитываются отдельно от новых.
4. Обновить показатели и таблицу истории здесь по receipt. Сохранить прежние
   партии и границы снимка. Неизвестное время и usage оставить неизвестными.
5. Просмотреть diff и проверку приватных данных, опубликовать отдельный commit/PR
   только с документами вики. Участники смогут видеть новую партию через GitHub.

Назначения ведутся в [приватном реестре](wiki-team-pipeline.md); эта страница —
его сводка для GitHub. Транскрипты TXT/SRT, корпус, аудио, Excel, базы,
receipts, приглашения и credentials остаются вне Git. Журнал обновляется
координатором после каждой партии; автоматической синхронизации пока нет.
