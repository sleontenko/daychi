## Реализовано в исходниках

- Три вкладки, расписание по умолчанию, переключение двух недель, время начала/конца
  в колонке, заголовок и палитра текущего макета. День и 14-дневный календарь остаются
  доступными через настройки; выбранный режим сохраняется локально.
- Компактная деталь с описанием наверху, раскрытие действий выбора, пропуск/возврат
  даты, подтверждение отмены регулярного выбора. Существующая модель выбора и ключи
  хранения сохранены. «Подписка» заменена формулировками о регулярном посещении.
- Настройки, авторы, форма обратной связи с локальным черновиком и валидацией.
  Кнопка открывает Telegram с draft text; пользователь завершает отправку там.
  **Нет утверждения о доставке**. Первый запуск бота может потребовать Start и ручную
  вставку текста. Реальный бот/получение сообщения не проверены, серверного приёма нет.
- Вики: Материалы / Словарь, честное отсутствие готовых определений, поиск термина
  в материалах. Повтор заголовка не отображается как содержательное описание.
- Android: package совпадает с существующим идентификатором проекта; local notification
  channel и permission path, системная форма Calendar, обработчики Back для деталей.
  Календарь остаётся отдельной копией, без Zoom и синхронизации отмен.
- Персональный сервер доступа, безопасное хранение сессии в SecureStore, проверка
  закрытых запросов, выход/отзыв и online-only gate. Закрытые данные сбрасываются из
  интерфейса при уходе приложения в фон или потере подтверждения доступа.
  Проверка сессии в активном приложении каждые 30 секунд; уже показанные данные не
  исчезают в ту же миллисекунду при серверном отзыве. Сервер отклоняет новый запрос сразу.
- `generated/catalog.json` и `generated/zoom.json` больше не импортируются. Публичные
  исправления трёх окончаний сохранены отдельно без реквизитов комнат.

## Сервер: подготовлено, не переключено

Новый entrypoint: `practice_api.daychee_app:app`. Старый сервис не менялся в работе.
Для подключения нужны:

- `WIKI_INDEX` — приватный оригинальный индекс;
- `WIKI_DATABASE` — **существующая** база identities из прежнего wiki API: нельзя
  создать новую и потерять совпадение стабильных material ID/закладок;
- `DAYCHEE_ACCESS_DATABASE` — отдельная приватная SQLite для приглашений/сессий;
- `DAYCHEE_ZOOM` — приватный JSON комнат на сервере;
- `EXPO_PUBLIC_DAYCHEE_API_URL` — HTTPS-адрес нового сервиса в приложении.

Без HTTPS-конфигурации вход закрыт; вики и Zoom в этой локальной версии не будут
открываться. Не переводить внутреннюю группу на неё до подключения и сквозной QA.
Нельзя использовать клиентский экран как замену серверной защите.

Администрирование только локальной командой:

```sh
.venv/bin/python scripts/daychee-invite.py --database data/daychee-access.sqlite3 issue
.venv/bin/python scripts/daychee-invite.py --database data/daychee-access.sqlite3 revoke --id ACCESS_ID
```

Команда `issue` выдаёт секретную ссылку; не сохранять вывод в публичных логах/Git.
URL использует fragment (`quietpractice://invite#TOKEN`), обмен — POST body.
Сессии и приглашения хранят только SHA-256 случайных 256-битных токенов; выдача
не имеет публичного HTTP endpoint. Погашение выполняется атомарно в SQLite.
После выхода ссылка не переиспользуется. Отзыв по access ID касается одного
приглашения/телефона. Сопоставление человека с несколькими access ID ведёт владелец.
Старый password login выключен только в новом entrypoint, совместимость старого сохранена.

Публичное расписание и личный выбор доступны без входа; закрыты вики и комнаты.
Рабочий HTTPS, конфигурация сервиса, TLS с реальных сетей и выдача людям ещё не выполнены.
Для store review нужен отдельно согласованный воспроизводимый доступ; обычная
одноразовая ссылка не решает повторную установку проверяющим. Такой доступ не создан.
