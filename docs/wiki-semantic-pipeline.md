# Темы, словарь и смысловые связи · пилот

[Прогресс](wiki-work-plan.md) · [Контент](wiki-production-pipeline.md)
· [Кандидат интерфейса](../design/candidates/wiki-semantics-2026-10-05/README.md).

Статус 05.10.2026: подготовлены и независимо проверены 10 страниц
(5 терминов, 5 тем), 14 утверждений и 16 связей с 12 материалами.
Четыре страницы объединяют несколько материалов. Импорт проверен локально;
новый интерфейс и пакет ещё не опубликованы на production.

## Принцип

Из проверенных полных текстов выделяем понятия и темы. Для каждого описания
указываем источники, а для каждой связи — точную цитату, таймкод и пояснение.
Другой редактор проверяет смысл по полному источнику. После проверки материал
получает ссылку на страницу понятия, а страница — обратные ссылки на материалы.
В графе появляется отдельный слой этих подтверждённых связей.

Общая страница помогает найти связанные уроки. Она не утверждает, что движения,
формы или значения слов в этих уроках одинаковы. Прямые связи между материалами
и между понятиями автоматически не создаются.

## Назначение и источники

Координатор резервирует batch_id и стабильные concept_id. Для пилота выбираются
только уже опубликованные `source_checked_draft` с подтверждённым отдельным
review полного текста. Прежние 45 конспектов без подтверждённой независимой
проверки в этот набор не входят. Наличие конспекта само по себе не доказывает review.

Приватный `assignment.json` содержит `batch_id`, `started_at`, массив `sources`:
каждый элемент содержит опубликованный `record` и `source` с путями TXT/SRT,
segments/info и их SHA-256. Record сохраняет resource_id, expected_title,
revision, summary, points, transcript/subtitles hashes и status.
Период исходного снимка не меняется. Новые материалы получают отдельные назначения.

Все полные тексты должны быть прочитаны редактором и проверяющим. Если они уже
читали их в предыдущей партии, допускается честно зафиксировать повторное
использование чтения при неизменных hashes и сохранённом доказательстве прежней
проверки. Контекст всех трёх опубликованных цитат каждого источника перечитывается. Это не новый полный проход.
В пилоте использованы 12 полных текстов, прочитанных обоими редакторами в партии 08,
и заново проверены 36 окон опубликованных цитат. Аудио не проверялось.

## Редактура

- `term`: термин с контекстным объяснением; `topic`: вопрос или тема нескольких
  фрагментов. Не выдавать тему за универсальное определение.
- Стабильный ID не меняется при уточнении заголовка. Синонимы добавляются только
  после проверки; похожее название не основание для объединения понятий.
- Каждое утверждение содержит `evidence_indexes` — индексы связей своей страницы.
  Каждая связь должна поддерживать хотя бы одно утверждение.
- Связь содержит resource_id, `relation` (`explains`, `practices`, `discusses`),
  пояснение `rationale` и `point_indexes`. Индексы адресуют опубликованные points,
  отсортированные по началу/концу/тексту, а не произвольный порядок массива.
- Пилот требует три опубликованных points на источник и использует только эти цитаты: текст и оба таймкода точные,
  без перевода, перефразирования или объединения несмежных фрагментов.
  Если их недостаточно, кандидат откладывается. Новый фрагмент сначала проходит
  обычную проверку источника и публикацию новой revision конспекта.
- Не добавлять неподтверждённые китайские названия, pinyin, инструкции движения,
  медицинские выводы или одобрение преподавателем.

`editorial.json` содержит `full_text_read`, `read_source_ids`, `pages` и notes.
Страница: concept_id, kind, title, aliases, revision, status,
`claims: [{text, evidence_indexes}]`, `links: [{resource_id, relation, rationale, point_indexes}]`.
Статус только `source_checked_draft`; 1–4 утверждения, 1–30 материалов на странице.

Другой проверяющий сохраняет `review.json`: editor/reviewer, SHA финального
editorial, verdict, full_text_read, read_source_ids, pages и SHA
`source-review-proof.json`. Каждая страница проверяется по ID, каждое утверждение
по claim_index/text/evidence_indexes, каждая связь по link_index/resource_id,
relation/rationale и точным point_refs. Для rationale и цитат нужны отдельные pass.
Source-reading/review proof сохраняют hashes, покрытие чтения и контексты.
Точный синтетический пример всех полей: [Fixture](../tests/test_wiki_semantic_batch.py).
Результат `needs_changes`/`blocked` не допускается к сборке.

## Сборка и импорт

Рабочие файлы остаются у координатора вне Git. Участникам не нужны admin credentials.

```sh
python -m scripts.wiki_semantic_batch \
  --assignment "$WIKI_SEMANTIC_ROOT/assignment.json" \
  --editorial "$WIKI_SEMANTIC_ROOT/editorial.json" \
  --review "$WIKI_SEMANTIC_ROOT/review.json" \
  --output "$WIKI_SEMANTIC_ROOT/batch.json"
python -m scripts.wiki_semantic_import --batch "$WIKI_SEMANTIC_ROOT/batch.json"
```

Сборщик проверяет hashes неизменных источников, соответствие каждого утверждения
и каждой связи финальному review и доказательства чтения. JSON и его hash берутся
из одного снимка байтов. Опубликованные цитаты выбираются в каноническом порядке.
`batch.json` содержит заголовок/редакцию источника, hashes TXT/SRT и точные points.
По умолчанию оба proof-файла читаются рядом с editorial/review; другие пути задаются
`--reading-proof`/`--review-proof`. Output не может перезаписать прочитанный источник
или доказательство.

После принятия кандидата и разрешённого выпуска координатор включает
`DAYCHEE_WIKI_SEMANTICS_ENABLED=1`, развёртывает проверенный код и импортирует:

```sh
python -m scripts.wiki_semantic_import \
  --batch "$WIKI_SEMANTIC_ROOT/batch.json" \
  --apply --password-file "$WIKI_OWNER_PASSWORD_FILE"
```

Флаг по умолчанию выключен. Owner endpoint `/api/admin/wiki/semantic-content`
использует существующие session, Origin и CSRF. Партия применяется атомарно вместе
с проверкой текущих content revisions. Повтор того же batch_id возвращает квитанцию
без переписывания страниц. Повтор старой квитанции не оживляет устаревшие связи.

Страница имеет неизменный тип и историю revisions. Изменение описания, связей,
источника или review получает новую revision и batch_id. Пакет заменяет всю
страницу: перед дополнением объединить её прежние связи и новые, сохранить чужие
назначения, снова проверить итоговый текст и все доказательства.
Конфликт alias с другой страницей отклоняется, автоматического слияния нет.

## Проверка результата и обновление

Reader показывает утверждения с номерами источников, обратные ссылки,
пояснение каждой связи, цитату и переход к видео с таймкодом.
Граф различает структуру, серии и связи материала с термином/темой.
Страницы понятий также входят в недавние публикации по фактической дате
обновления, с обычным заголовком и датой под ним.
Публичный DTO содержит только читательские поля, без рабочих hashes/reviewer/proof.
Существующие флаги доступа к публичной и закрытой вики сохраняются.

Если источник переименован, неоднозначен, отвязан или изменились его revision,
hashes/цитата, **вся страница** скрывается вместе с узлом и обратными ссылками
до новой проверки. API читает content и semantic pages из общего снимка базы.
Отключение semantic-флага скрывает слой, сохраняя рабочие версии для восстановления.

После импорта сверить все claims/links/quotes, graph и backlinks, повтор импорта,
неизменность исходных конспектов, anonymous/auth/public flags и UI состояния.
Квитанции и реальный контент — вне Git. В Git идут код, синтетические тесты/QA
и подтверждённые показатели. Обновлять work-plan отдельно от количества импортов
материалов: 10 страниц словаря не равны 10 новым конспектам.

Следующий объём: ещё 12 независимо проверенных материалов; 30–90 минут редакционной
работы предварительно, в зависимости от числа новых/уже существующих понятий.
Нельзя экстраполировать число страниц на весь корпус. В группе из 101 нового
проверенного материала ещё 89 не обработаны этим семантическим проходом.

Совместимость: новые узлы графа выдаются только при `?semantics=1` и включённом
feature flag. Старые клиенты, включая существующий native binary, получают
прежний граф. Новый веб-клиент запрашивает слой явно; native host пока этого не делает.
