## Назначение и обновление

1. Координатор назначает по 3 стабильных ID, ответственного, проверяющего и batch_id.
2. Проверить прежние назначения, доступность и пригодный текст.
   ASR: Да / Нет / Уточнить. Неизвестная длительность остаётся неизвестной.
3. Редактор возвращает конспект и evidence по [протоколу](wiki-contributor-pipeline.md).
4. Проверяющий ставит pass / needs_changes / blocked с причиной.
5. Координатор валидирует и импортирует; статус импорта — только по receipt.
6. Фактическое время и usage записываются отдельно от оценок.

Импорт не заменяет редакционную проверку. Один ресурс может относиться
к нескольким карточкам; неоднозначность разбирается до назначения.
Два источника одной карточки нельзя импортировать независимо с одной revision.

## Сохранность реестра

Жёлтые поля — вводы, R:W — формулы, A:E — идентичность и исходный период.
Новые строки объединяются по стабильному ID с сохранением назначений и истории.
Не пересобирать таблицу поверх пользовательских правок.

Новые находки относятся к датированным группам; знаменатель старого снимка
не переписывается. Синхронизация учитывает новые и изменённые сообщения.
Изменение ссылки/hash требует проверки; недоступность не доказывает удаление.
Автоматический updater пока не реализован.

При добавлении строк расширять Excel Table, формулы и валидации.
Сводка рассчитана на строки 6–5000; при превышении расширить диапазоны.
Нормативы аудио не применяются автоматически к PDF/контейнерам.
