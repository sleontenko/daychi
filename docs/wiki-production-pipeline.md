## Выбранный процесс

1. Сначала использовать уже имеющиеся TXT/SRT, точно сопоставленные с карточкой
   по YouTube ID. Проверять хеши источников и название; не искать соответствия
   только по похожему заголовку. Telegram-синхронизация с актуальной авторизацией
   на MacBook остаётся отдельной задачей и не блокирует эту очередь.
2. Для записей без расшифровки: аудио 16 kHz mono → Silero VAD с сохранением
   смещений → локальные Whisper large-v3-turbo и Parakeet. Расхождения и аномалии
   направлять в возобновляемую очередь; Qwen ASR подключать только к спорным
   коротким фрагментам с ограничением времени/токенов. NotebookLM остаётся
   альтернативой для отдельных источников, не обязательным этапом.
3. Редактор готовит 2–4 предложения по полному тексту, сохраняет происхождение,
   вопросы и неопределённые термины. Отдельный проход проверяет утверждения по
   источнику. Совпадение ASR-моделей — машинная опора, не истинный эталон и не
   измеренная точность. Неразрешённые расхождения не превращать в определения.
4. В существующую приватную вики добавлять явно помеченные «Конспект по
   расшифровке · черновик» и точные цитаты с таймкодами. Обогащение хранить
   отдельно от исходного каталога; сохранять версии и идемпотентный ID партии.
   Слова «одобрено преподавателем» требуют отдельного фактического одобрения.
5. После каждой партии проверять источники, все импортированные карточки,
   неизменность исходных полей, повторный импорт и закрытость данных.

Выбор опирается на завершённый локальный пилот и диагностику:
[очередь ASR](wiki-asr-queue-2026-09-30.md),
[диагностика](wiki-asr-diagnostics-2026-09-30.md).
Платные ASR API для этого процесса не нужны.

## Первая партия

39 аннотаций из существующего редакционного пилота: 7 + 32; 117 фрагментов
расшифровок. Это дополнение к существующим карточкам, а не 39 новых видео и не
готовый словарь. Субтитры могут содержать ошибки распознавания; автоматическая
проверка цитат не подтверждает правильность самого ASR или весь смысл конспекта.
Старые статусы `needs_editorial_review` и вопросы редакционного пилота сохранены.

Для цитат удаляются перекрытия бегущих субтитров, добавляется предложение из
того же исходника и сохраняется временной интервал. Цитаты — тематические
фрагменты для перехода к записи, не доказательство каждой фразы пересказа.

Приватный файл партии: `data/wiki-enrichment/2026-09-30/batch.json` (вне Git).
Сборка: `python -m scripts.wiki_enrichment_batch --help`.
Импорт: `python -m scripts.wiki_enrichment_import --batch <private-json>` сначала
проверяет файл локально; `--apply --password-file <existing-owner-password-file>`
выполняет импорт. Endpoint `/api/admin/wiki/content`, только существующая сессия организатора,
Origin + CSRF; участнический токен не даёт права импорта. На серверном volume
создаётся отдельная `wiki-content.sqlite3`; архивы исходного каталога не меняются.

Следующий объём: источники текущего индекса без TXT/SRT, небольшие партии через
выбранную ASR-очередь. Сначала устранить/изолировать оставшиеся спорные фрагменты
пилота; затем наращивать покрытие. Термины, полноценные статьи и смысловые связи
требуют отдельного редакционного прохода по подтверждённым источникам.
