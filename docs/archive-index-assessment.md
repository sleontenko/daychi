# Индекс Никиты: результат импорта и предложение следующего этапа

Проверено 19 сентября 2026. Это исследование и предложение, не изменение
согласованной навигации или обещание выпуска.

Уточнение владельца после исследования: следующим этапом делаем вики;
карту развития и последовательность обучения пока не трогаем. Актуальный
трёхшаговый план — [WIKI_PLAN.md](WIKI_PLAN.md); предложения о карте ниже
остаются возможностями на будущее и не входят в этот этап.

## Что получено

Источник: https://lessons-archive-production.up.railway.app/ (закрытый архив).
Авторизованный вход и чтение работают. Сохранён полный индекс, а не только
первые 300 карточек, которыми ограничен интерфейс сайта.

- 1 111 базовых записей + 34 ручных дополнения = **1 145 записей**.
- Список исключённых исходных временных меток пуст; импорт учитывает его при
  будущих выгрузках так же, как интерфейс источника.
- 13 категорий, 319 пар «категория / ключ подтемы».
- Даты в источнике: 15 июня 2025 — 18 сентября 2026.
- 1 168 ссылок, 1 156 различных точных URL; 7 групп повторяющихся URL.
- Форматы по классификации источника: video 720, Drive 283, Zoom 125,
  article 13, doc 4. Это типы источника, не проверенные MIME-типы файлов.
- Ни одной записи без ссылки; дубликатов рассчитанных идентификаторов нет.
- У 970 записей уровень не указан. Остальные: новички 60, старшая группа 81,
  средняя группа 30, продвинутые 4.

Источник сообщает генерацию 2026-09-19T10:53:53.018Z; последние записи — за
18 сентября. Поэтому гипотеза об устаревшем слепке не подтверждается.
В коде страницы есть слияние базового индекса с ручными дополнениями и
исключениями. Это не доказывает автоматическое обновление: частота, механизм
и полнота поступления новых занятий пока неизвестны.

## Локальные результаты

Приватная папка `data/nikita-archive/2026-09-19/` исключена существующим
`.gitignore`. Каталог имеет права 700, файлы — 600.

- `index.json`: нормализованные записи с полным исходным объектом.
- `taxonomy.json`: категории и подтемы со счётчиками по итоговому набору.
- `manifest.json`: объёмы, диапазон дат, ограничения и SHA-256 исходных файлов.
- `source.html`, `lessons.js`, `extra.js`: исходный снимок для повторного разбора.

Пароль входа и cookie не сохранены. Исходные записи могут содержать коды доступа
к Zoom: весь снимок остаётся приватным. Отображаемое нормализованное название
очищено от URL и конструкции «Код доступа». Это не обезличивание исходного текста.
Видео, аудио, PDF и транскрипты не скачивались; доступность всех ссылок не проверена.

Повторный импорт: `python3 scripts/import_lessons_archive.py --output data/nikita-archive/NEW_DATE`.
Пароль вводится скрытым приглашением либо передаётся через переменную окружения
`LESSONS_ARCHIVE_PASSWORD`; не записывать его в команду, документацию или Git.
Повторный разбор существующего снимка: добавить `--offline`.
Загруженный JavaScript не исполняется: извлекаются только JSON-значения присваиваний.
Существующий снимок лучше сохранять неизменным, выбирая новую папку для обновления.

## Как использовать в принятом дизайне

Основа: `DESIGN.md`, `PRODUCT.md`, `ROADMAP.md`, фактические данные прототипа.
В рабочем приложении сейчас «Сегодня / Расписание / Мои занятия».
«Карта» и «Вики» остаются демонстрационными. Новый индекс делает следующий
срез библиотеки возможным, но сам по себе не делает эти экраны готовыми.

| Поверхность | Что даёт индекс | Что ещё требуется |
|---|---|---|
| Библиотека на основе экрана вики | Реальные направления, темы, поиск по названиям и исходным описаниям | Согласовать место в навигации, закрытый доступ, состояния загрузки и ошибки |
| Детали материала | Название, дата, тема, несколько ссылок, исходное описание | Чистое отображение, обозначение провайдера, обработка недоступной записи |
| Сегодня | Материалы для выбранного направления, сохранённая запись для повторения | Явная связь с интересом пользователя; связь с конкретным занятием нельзя выводить только из даты |
| Карта практики | Подборки и серии, например веер и формы дракона | Учитель подтверждает порядок, prerequisites и критерии освоения |
| Вики знаний | Список кандидатов на понятия и соответствующие им записи | Транскрипты/тексты, проверенные определения и ссылки на фрагменты |
| Плеер | Ссылки для открытия оригинальной записи | Тип медиа, длительность, разрешённый способ воспроизведения, реальные таймкоды |

Сохранить кремовую основу, спокойные сгруппированные списки, системный шрифт,
терракотовые и шалфейные акценты. Строка записи: название, ниже дата и источник;
детали открываются отдельно. Технический провайдер не должен подменять тему:
в первую очередь пользователь выбирает направление и материал.

Предлагаемый первый сценарий: **Библиотека → Веер → Младшая группа → запись →
открыть оригинал → сохранить для повторения**. В архиве 129 записей о веере,
из них 56 в подтеме «Младшая группа», 69 — «Старшая группа», 4 без подтемы.
Это проверяемый срез с реальными данными без ожидания полной обработки корпуса.
Для первого этапа достаточно открытия исходного материала; встроенное
воспроизведение и автоматическое измерение прогресса — отдельная работа.

## Качество данных и связь с существующим корпусом

1. Сохранить исходную таксономию, а поверх неё вести согласованный словарь.
   Например, у дракона «9 Форма» и «Форма 9» — разные исходные подтемы.
   У нэйгун 70 записей в «Разное». Автоматическое превращение всех 319 подтем
   в полноценные статьи создаст много слабых страниц.
2. Разделять направление, аудиторию, практику и серию: «Средняя группа» —
   аудитория, «Дракон» — практика, «Статьи и материалы» — тип раздела.
3. Повтор URL не означает повтор занятия: один плейлист или материал может
   встречаться в нескольких публикациях. Сохранять связь «публикация → ресурс».
4. Соединять с прежним корпусом по каноническим YouTube video ID / Drive file ID,
   а не по похожему названию. Сопоставление ещё не выполнено: данные старого
   корпуса не входят в этот репозиторий.
5. В `practice_api/repository.py` уже есть каталог, темы и поиск по данным
   старого ingestion-плана. Разумно добавить адаптер нового источника к этому
   контракту, сохранив происхождение; работающий клиент не должен зависеть от
   HTML Никиты при каждом открытии экрана.
6. Базовый индекс не даёт устойчивого ID публикации. Сейчас ID рассчитан из
   временной метки и набора ссылок; ручные дополнения имеют собственный ID.
   Изменение ссылок потребует сверки, а не безусловного добавления новой записи.
7. При обновлении сохранять новый снимок и отчёт добавлено/изменено/исключено.
   Отсутствие записи в одном неудачном импорте не должно удалять личные сохранения.

## Предлагаемая последовательность, требует согласования

1. Закрытый каталог: поиск, направления/подтемы, детали, оригинальная ссылка,
   локальное сохранение. Проверить на нескольких реальных учениках и iPhone.
2. Связать каталог с «Сегодня» через выбранное направление и материалы для
   повторения; связи записи с конкретной встречей подтверждать отдельно.
3. Подготовить одну учебную подборку с учителем; после проверки пользы добавлять
   карту, заметки и осмысленный прогресс.
4. Обогащать выбранные записи транскриптами и проверенными объяснениями для вики.

Перед подключением в распространяемое приложение нужно выбрать аудиторию и
способ закрытого доступа. Публичное расписание остаётся доступным без входа;
библиотечный пароль нельзя зашивать в Expo bundle или публичный API.
Отдельно выяснить у Никиты механизм обновления и возможность стабильного экспорта.
Контактов с Никитой в рамках этой работы не было.

## Проверки и границы результата

Авторизованный интерфейс показал 1 145 записей и те же 13 счётчиков категорий,
что получены после слияния исходных файлов. Проверены JSON, счётчики, обязательные
поля, схемы ссылок, отсутствие пустых ссылок и коллизий ID. Исходный код парсера
дополнительно проверен на синтетическом исключении/дополнении записи.
Git игнорирует весь снимок. Приложение, API и TestFlight не менялись.
Сквозной вход нового CLI ещё не проверен: онлайн-снимок получен отдельным
скриптом с тем же HTTP-механизмом; новый CLI проверен на его офлайн-разборе.
