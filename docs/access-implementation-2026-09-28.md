Владелец разрешил реализацию, следующую TestFlight и Android-сборку. Перенос

## Согласованный UX

Владелец одобрил шесть изображений `qa-design-repair/access-preview/01.png`–`06.png`
из кандидата Claude Design «Дейчи - доступ к вики и Zoom.dc.html». Затем одобрил
уточнение: ссылка передаёт приглашение, активация только по явному нажатию;
после установки нажать ссылку снова, ручной код — запасной путь. Не обещать
автоматический перенос ссылки через установку приложения. После активации
вернуться к исходному материалу/занятию; при холодном старте открыть вики.

## Реализовано в рабочих исходниках

- Закрытая вики с инструкцией, форма кода/ссылки и явная активация.
- Экран результата и разные ответы expired/used/revoked/invalid.
- Возврат из доступа к исходному экрану, сохранение выбора материала.
- При уже открытом доступе новая ссылка позволяет продолжить без повторной активации.
- Вкладки сохраняют открытое занятие и его позицию; смена вкладки очищает старую
  цель возврата из доступа.
- Zoom: загрузка, отсутствие ссылки, ошибка, завершённое/отменённое занятие.

Новый API-контракт: неуспешная активация возвращает HTTP 401 с
`{"detail":{"code":"expired|used|revoked|invalid"}}`. Старый сервер остаётся
совместимым, но показывает общую ошибку. Отдельной deployment-задаче нужно
включить актуальные `practice_api/daychee_app.py` и `practice_api/invitations.py`.
Секреты/production-приглашения в QA не использовались.
