# Вики: локальная реализация первого этапа

Первоначальный отчёт локальной реализации от 19 сентября 2026.
Обновление: build 6 доступен внутренней группе TestFlight (Testing); защищённый
HTTPS API развёрнут по явному разрешению владельца. История проверок — ниже.

## Решение владельца

Общий логин/пароль без регистрации, как у исходного архива. Полноценные аккаунты
отложены. Карта развития и последовательность обучения остаются вне этапа.

## Реализовано

- Четвёртая вкладка «Вики» в рабочем приложении; поиск, рубрики и подтемы,
  сортировка, страницы по 40 записей, детали и исходные ссылки.
- Закладки содержат только ID и хранятся на устройстве; недоступную запись
  можно убрать. Изменение названия/ссылок публикации с уникальной временной
  меткой сохраняет внутренний ID. Сложные коллизии источника требуют ручной сверки.
- Общие credentials задаются только на сервере. Случайная сессия на 30 дней,
  хранение её хеша в SQLite; выход отзывает сессию, смена credentials инвалидирует
  старые сессии. Сессия iOS хранится в SecureStore, пароль не сохраняется клиентом.
- Web preview хранит сессию только в памяти: после перезагрузки нужен вход.
  Закладки web сохраняются, но приватные названия/описания на диск не пишутся.
- Защищены все методы каталога. Нет публичного экспорта, сырых исходных объектов,
  credentials в клиенте, URL/кодов Zoom в поисковой выдаче или HTTP access log.
- Ограничение входа: 10 попыток за 10 минут на IP, один процесс сервера.
  За reverse proxy доверять forwarded IP только своему proxy; без этого несколько
  учеников могут разделять один лимит. Распределённый limiter пока не реализован.
- Клиент принимает HTTPS; HTTP разрешён только в development на loopback.
- Закрытого офлайн-каталога нет; после выхода данные убираются из памяти.
  При сетевом сбое выхода сессия остаётся на экране для повторной попытки.

## Запуск

```sh
python3.12 -m venv .venv
.venv/bin/pip install -r scripts/wiki-requirements.txt
# Задать WIKI_USERNAME и WIKI_PASSWORD через окружение либо локальный secret manager.
.venv/bin/uvicorn practice_api.wiki_app:app --host 127.0.0.1 --port 8766 --no-access-log
```

Переменные сервера: `WIKI_USERNAME`, `WIKI_PASSWORD`, `WIKI_INDEX`,
`WIKI_DATABASE`, `WIKI_ORIGINS` (точные разрешённые web origins через запятую).
Без credentials API закрыт (503); без корректной сессии каталог не выдаётся.
SQLite — постоянное хранилище ID и сессий: сохранять и резервировать вместе
с приватным каталогом, не заменять пустой базой при обновлениях.

В этой рабочей папке есть игнорируемый `data/wiki-local.json` с предоставленным
владельцем общим входом, права 600. Скрипт `.venv/bin/python scripts/run_wiki_local.py`
читает его и запускает API только на loopback, без HTTP access log.
Не переносить этот файл в Git, клиент или публичные артефакты.

Клиент: `EXPO_PUBLIC_WIKI_API_URL` — адрес только этого API, не старого
`practice_api.app` и не публичного сервиса расписания. Для preview:

```sh
cd apps/practice-app
EXPO_PUBLIC_WIKI_API_URL=http://127.0.0.1:8766 npx expo start --web --port 8082 --localhost
```

Сервис намеренно выделен в `practice_api/wiki_app.py`: старый API корпуса
остаётся локальным и не становится безопасным для публикации от появления вики.
Схему поиска не связываем с AI-провайдерами или старой ingestion-базой.

Обновление: повторно импортировать архив в новую приватную папку, проверить diff,
затем заменить `WIKI_INDEX`/перезапустить API, сохранив `WIKI_DATABASE`.
Внутри работающего процесса невалидный новый снимок оставляет последний корректный
каталог. После перезапуска без корректного снимка сервер отдаёт 503.
Автоматического поступления новых материалов от Никиты нет.

## Проверки

- TypeScript, lint и 14 существующих JS-тестов расписания прошли.
- 40 backend-тестов прошли: 4 сценария вики и 36 существующих сценариев
  расписания/напоминаний/APNs. Вики проверяет защиту каталога, неверный пароль,
  отзыв/истечение/ротацию сессий, throttling, очищенную выдачу, поиск ё/е,
  пагинацию 315 записей, стабильность ID при исправлении и после перезапуска,
  невалидный снимок и отсутствующую конфигурацию.
- В браузере с реальным индексом: 1 145 записей; «Веер» → «Младшая группа»
  даёт 56; детали, сохранение и возврат к выбранным фильтрам проверены.
- Композиция проверена в web viewport 390×844. Web: после перезагрузки и повторного
  входа закладка сохранена; выход возвращает форму входа и убирает каталог.
- Debug-сборка и запуск на iPhone 18 Pro Simulator / iOS 27 успешны. Проверены
  вход с реальным индексом (1 145), детали, сохранение, полный stop/launch:
  сессия восстановилась без повторного ввода, закладка сохранилась.
- Первоначальная сборка с CODE_SIGNING_ALLOWED=NO дала ошибку Keychain также
  в expo-notifications. Пересборка с CODE_SIGNING_ALLOWED=YES и локальной ad-hoc
  подписью CODE_SIGN_IDENTITY=- устранила её; изменения исходников для этого
  не понадобились. Это подпись Simulator, не подтверждение device/TestFlight signing.
- Нативные предупреждения сторонних библиотек остаются. Проверки Simulator
  не заменяют физический iPhone и не подтверждают воспроизведение всех ссылок.

## До распространения

Разместить этот API за HTTPS на согласованном хосте, настроить credentials
в серверном окружении и URL в сборке. Отдельно проверить
VoiceOver/Dynamic Type, внешние источники и реальный iPhone. Подписанный архив, обновление номера
сборки и отправка TestFlight требуют отдельного разрешения. Шаги 2–3 вики
(«Сегодня» и редакционное обогащение) пока не реализованы.

Документация Expo, проверенная перед работой:
https://docs.expo.dev/versions/v57.0.0/ .

DESIGN.md; автоматический detector не запускался.

Проверено: TypeScript, lint; web 390×844, неверный пароль, показ/скрытие,
успешный вход с новой парой. Нативная debug-сборка запущена, но повторная

### Production HTTPS — 19 сентября 2026

После явного разрешения владельца API запущен отдельным launch agent
`ai.mypraxis.quietpractice.wiki` на Mac mini, loopback 8767. Production-копия:
`~/projects/quiet-practice-wiki-release`; приватные данные и серверная конфигурация:
`~/.config/quiet-practice/wiki/`. Постоянный SQLite сохранён при переносе.

Funnel публикует только `/api/wiki` на существующем HTTPS-хосте
`mac-mini-server.tail07600a.ts.net`, upstream `http://127.0.0.1:8767/api/wiki`.
Маршрут расписания остаётся прежним. Старый API корпуса не публиковался.
HTTPS-проверка: анонимный запрос 401; вход, каталог 1145, поиск и детали успешны;
ответы no-store; logout отзывает токен (401); расписание `/health` = 200.
Сборка 6 содержит этот HTTPS-хост, без loopback URL вики.
